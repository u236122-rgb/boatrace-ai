# 競艇AI予想ツール（boatrace-ai）

ボートレース（競艇）の公式データ（2021年〜、全24場・約30万レース）を自動で集めて、
機械学習（LightGBM）で各艇の1着確率を予測し、3連単の買い目を出す個人開発のツールです。

- データ収集（公式ファイルの自動ダウンロード、オッズのスクレイピング）から、学習・予測・検証・PC/スマホ向けの画面までを一人で作りました。
- 開発には生成AI（Claude）を活用しています。

> ※ 個人の学習・研究用です。舟券の購入を勧めるものではありません。

## 主な機能

| 機能 | 内容 | ファイル |
|---|---|---|
| データ自動更新 | 公式サイトの番組表（B）・競走成績（K）を不足日だけダウンロードし、展開・解析してCSVに追記 | `update_data.py`, `program.py` |
| オッズ自動収集 | boatrace.jp から3連単120通りのオッズを締切15・13・10・5分前に取得。Windowsのタスクスケジューラで常駐 | `odds_collector.py`, `register_odds_task.ps1` |
| 学習 | 出走表と結果を結合し、LightGBMで「その艇が1着になる確率」を学習 | `build_model.py` |
| 予測 | 6艇の強さから3連単120通りの確率を計算（Plackett-Luce）し、本命・中穴・大穴に振り分け | `core.py` |
| PC用画面 | tkinter製GUI。番組表からワンクリック入力、当日全レースの一括予想、CSV保存 | `予想GUI.py`, `app.py` |
| スマホ用画面 | 標準ライブラリだけで動くWebサーバ。Basic認証つき。Cloudflare Tunnelで外出先からも利用可 | `web.py`, `tunnel.py` |
| 検証 | 改善案を1つずつ、リークの無い方法で検証するスクリプト | `exp_*.py`, `experiments.py`, `venue_backtest.py`, `ev_backtest.py` |

## 仕組み

    公式データ(B/K) ──► update_data.py ──► data/csv/（entries / results / payouts）
    boatrace.jp オッズ ──► odds_collector.py ──► data/odds/
                                   ▼
                     build_model.py（特徴量作成＋LightGBM学習）
                                   ▼
                     core.py（1着確率 → 3連単確率 → 買い目）
                                   ▼
                     予想GUI.py（PC） / web.py（スマホ）

主な特徴量（約30個）
- 枠番、場、級別、年齢、体重、全国/当地の勝率・2連率、モーター・ボートの2連率
- 天候・風向・風速・波高
- 選手の実績（登録番号から自動計算）：コース別の勝率・2連率・平均ST、当地実績、通算平均ST
- 節間モーター成績（その節の前日までのモーター2連率）
- 展示タイム（直前情報。手入力した場合のみ使用）
- 件数が少ない実績はベイズ収縮で全体平均に寄せてノイズを抑える

## 検証の方針と結果

「リークの無い検証で効果を確かめてから採用する。効かなければ正直に『効果なし』と記録する」をルールにしています。

- 時系列分割：2024年末までで学習 → 2025年以降で検証（未来のデータで試す）
- Leave-One-Out：選手の実績を計算するとき、そのレース自身の結果を除外
- 複数seed・複数年で結果が安定しているかを確認
- 過学習・リークを放置した場合に「見かけの好成績」がどれだけ出るかも比較（`exp_overfit_sim.py`）

結果
- 本命1点の1着的中率：約57%（1コースを機械的に買い続けた場合は約55.8%）
- 効いた改善：モデルを単純にして強く正則化（2024年 +1.30pt / 2025年 +1.02pt、全seedで改善）、節間モーター成績の追加（+0.25pt）
- 効果がなかったもの：特徴量の交互作用、アンサンブル、ハイパーパラメータの細かい調整 など
- 回収率：確定オッズで機械的に買うと控除率（約25%）に勝てない（一番よくても本命の単勝で約94〜98%）

## ファイル構成

本体
- `update_data.py` 公式データのダウンロード・解析・CSV更新
- `program.py` 番組表（B）の解析
- `build_payouts_all.py` 全券種の払戻金をまとめる
- `odds_collector.py` / `register_odds_task.ps1` 3連単オッズの自動収集と常駐登録
- `build_model.py` 特徴量作成と学習
- `core.py` 予測エンジン
- `予想GUI.py` / `app.py` PC用GUI
- `web.py` / `tunnel.py` スマホ用Webサーバ／外部公開

検証
- `experiments.py` 交互作用・ハイパーパラメータ・アンサンブルの効果
- `exp_simplify.py` 単純なモデルのほうが未来のデータに強いか
- `exp_motor_setsu.py` 節間モーター成績を足すと精度が上がるか
- `exp_overfit_sim.py` 過学習・リークを放置すると見かけの成績がどれだけ良くなるか
- `exp_ml_pitfalls.py` 古いデータだけで学習すると最近の精度が落ちるか
- `exp_bettype_roi.py` / `exp_selective_roi.py` 券種ごと・条件を絞った場合の回収率
- `venue_backtest.py` 24場×季節ごとの的中率・回収率
- `ev_backtest.py` モデル確率×実オッズ（期待値）で買った場合の回収率

## 使い方

    pip install -r requirements.txt
    python update_data.py    # データ更新
    python build_model.py    # 学習
    python app.py            # PC用GUI
    python web.py            # スマホ用（同じWi-Fiで http://<PCのIP>:8000）

- データ（約1.5GB）と学習済みモデルは含めていません（容量が大きいことと、公式サイト由来のデータのため）。
- `update_data.py` は、既存のCSVに公式サイトから不足分を追記する仕組みです。
- 外部公開（`tunnel.py`）には、環境変数 `KYOTEI_WEB_PASSWORD` でパスワードの設定が必要です。
- オッズ収集は、サーバに負荷をかけないようアクセスを3秒以上空けています。

## 自己考察

### このプログラムの弱点

1. 大穴は見つけられない
   確率が高い組み合わせを選ぶ仕組みのため、当たりやすいレースが当たり、大穴は拾えません。
   大穴（1万円超）を当てる専用モデルも試しましたが、AUC 0.563 で、原理的に当てにくいと分かりました。

2. 節の序盤は精度が上がりにくい（仮説）
   節（開催）の前半は、その節でのモーターの調子や水面の状態が見えていないため、後半にならないと精度が上がらないと考えています。
   節の前日までのモーター成績を特徴量に加えたところ精度が上がった（+0.25pt）ので、節の途中で分かる情報が効くことは確かめられました。
   節の日目ごとの精度を出せば、序盤が弱いかどうかを数字で確かめられます。

3. モーターの当たり外れが読み切れない
   モーターは節の初日にくじで割り当てられ、その節の間使います。前の節と同じ性能のモーターが当たるとは限らず、当たり外れが大きく出ます。
   さらに、選手が自分で行う整備の腕も結果に影響しますが、これもデータに入っていません。

4. 転覆の影響が入っていない
   転覆するとモーターにダメージが入り、分解整備（オーバーホール）をするため、性能が落ちると考えています。この影響がモデルに入っていません。
   （参考：手元のデータでは、事故・失格のあった選手は、同じ日の次のレースで勝率が約5ポイント下がっていました。ただし転覆だけの影響は切り分けられていません。）

5. 相手が人間なので、ばらつきが大きい
   過学習を避ける工夫はしていますが、予想の対象が人間なので、同じ条件でも結果にムラが出ます。

### 結論
このプログラムは、的中を保証するものではありません。自分で予想するときの「参考材料」として使うのが適切だと考えています。

### 今後の課題
1. オッズの歪みを見つける
   確率が高いのに、他の人があまり買っていない目を探します（期待値 = 予想確率 × オッズ）。
   そのために、締切直前のオッズを自動で集める仕組みを作り、検証を始めています。
2. モーターと選手の相性を見極める
   モーターの性能によって、選手の能力がどれだけ変わるのかを、まだ見極められていません。
3. 足りない情報を補う
   転覆の履歴、整備の状況、節の日目など、今のモデルが使っていない情報を加えます。
